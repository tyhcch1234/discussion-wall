# 討論牆 Discussion Wall

一個類似 **Padlet** 的網上討論牆：**主持人出題 → 參加者逐題貼上答案**。
首頁先列出所有討論題目，撳入任何一條題目才看到該題的討論內容。
純前端單檔（`index.html`），可直接放在 GitHub Pages。

🔗 **網址**：https://tyhcch1234.github.io/discussion-wall/

---

## 頁面結構

```
首頁（所有題目）
 ├─ ① 本週討論      12 張答案 · 最後更新 3 分鐘前
 ├─ ② 社交媒體影響   5 張答案
 └─ ③ 自由分享       0 張答案
        ↓ 撳入
題目頁
 ├─ 題目：Q2 你認為社交媒體有咩影響？
 ├─ 說明：請舉一個例子，並講下係好事定壞事。
 └─ 答案牆（所有參加者貼上的卡片）＋ 底部輸入框
```

## 功能

| 功能 | 說明 |
| --- | --- |
| 題目／答案兩層 | 首頁總覽所有題目（答案數、最後更新時間），撳入先睇該題討論 |
| 主持人出題 | 管理員可新增／編輯題目，包括題目名稱、補充說明、卡片主題色 |
| 多人共用 | 答案即時同步到雲端，其他人每 12 秒自動更新，切換分頁回來即時更新 |
| 彩色卡片 | 6 種顏色，方便分類不同意見 |
| 讚好 | 可按 ❤️，亦可切換「最多讚優先」排序 |
| 匿名 | 貼答案時勾選「匿名」，只顯示「匿名」 |
| 名字記憶 | 名字只存在自己裝置（localStorage），不用註冊、不用登入 |
| 管理員 | 可出題、改題、刪題、刪任何卡片、匯出／匯入備份 |
| 日／夜模式 | 自動跟隨系統，也可手動切換 |
| 深層連結 | `#t=<題目ID>`，可直接分享某一條題目 |

## 使用流程

**主持人**
1. 開網址 → 右上 ⚙️ → 輸入管理密碼 → 「＋ 新增題目」。
2. 填題目名稱、補充說明、揀顏色 → 確定，會自動進入該題目頁。
3. 把該題目頁的「🔗 分享」連結傳給參加者。

**參加者**
1. 開連結 → 右上角名字改成自己名字（只需一次）。
2. 撳想答的題目 → 底部輸入答案 → 揀顏色 → 「貼上牆」。

**預設管理密碼：`teach2026`**

## 自行更改管理密碼（不需要改程式碼）

1. 右上 ⚙️ → 輸入目前密碼 → 進入「管理員工具」。
2. 按「🔑 更改管理密碼」→ 輸入目前密碼 + 新密碼兩次（最少 4 個字元）→ 更新。
3. 即時生效：**所有裝置、所有老師**下一次登入都要用新密碼。

技術細節：
- 密碼不是明文儲存，而是 `SHA-256(salt + 密碼)` 的雜湊，存在雲端 `cfg:auth`。
- 在非 https 環境（例如直接用瀏覽器開檔案）會自動改用備援雜湊，仍然可以正常登入。
- 設定頁會顯示「密碼來源：自訂（YYYY-MM-DD 更新）」或「預設」。

### 忘記密碼怎辦（重設）

管理員密碼只存在雲端，無法在頁面上「找回」，但可以覆寫：

1. 打開 `index.html`，把 `CONFIG.ADMIN_PASS` 改成新密碼。
2. 同時把 `CONFIG.AUTH_EPOCH: 1` 改成 `2`（下次改就 3、4…）。
3. commit + push。重新開頁後就用新的 `ADMIN_PASS` 登入，雲端舊密碼紀錄會被忽略。

> ⚠️ 這是純前端的「軟鎖」：只適合課堂防止同學亂刪卡片，不是真正的帳戶安全。任何知道網址的人都可以貼答案；原始碼中亦可見預設密碼，所以**第一次使用就應該改密碼**。

## 資料儲存

預設使用免費雲端 [kvdb.io](https://kvdb.io)（`CONFIG.KVDB_BUCKET`），所以**不需要後端、不需要資料庫**就能跨裝置共用。

- `cfg:topics` → 題目清單（名稱、說明、顏色）
- `p:<題目ID>:<卡片ID>` → 每張答案（分開一個 key，幾個人同時貼都唔會撞）

若雲端連不上，頁面會自動切換到「本機模式」（只儲存在該裝置），並在頂部顯示提示。

### ⚠️ 重要：免費 bucket 有期限

此專案的 bucket 是以匿名方式建立，未驗證 email 的免費 bucket 資料會在建立後約 **30 天**失效。
若要長期使用（整個學期），建議二選一：

**A. 匯出備份（最簡單）**
管理員 → ⚙️ → 「匯出備份」下載 JSON；需要時再「匯入備份」。

**B. 換成永久免費的 Firebase（建議，5–10 分鐘）**
1. 到 <https://console.firebase.google.com> 建立專案 → 新增「Realtime Database」→ 測試模式。
2. 專案設定 → 一般 → 你的應用程式 → 取得 `databaseURL`。
3. 把 `makeCloudStore()` 換成 Firebase REST 版本（或把 bucket 換成已用 email 驗證的 kvdb bucket），再 push 即可。

需要的話可以請 AI 幫你接上 Firebase，只需提供 `databaseURL`。

> 🔒 隱私：這是公開的課堂討論板，bucket id 寫在原始碼中，任何拿到網址的人都能讀寫；請勿張貼個人敏感資料。
